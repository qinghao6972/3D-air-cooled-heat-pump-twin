# 风冷热泵控制系统 · 数字孪生（Three.js 前端）

基于 Blender 导出的 `IndustrialPlantRoom.glb`（3074 节点 / 951 网格 / 29 材质 / 6.4 MB），
使用 **three.js r186** 在浏览器中实时渲染的 1000 m² 制冷机房数字孪生场景。
纯前端、零后端、零构建步骤 —— 双击 `启动.bat` 即可运行。

---

## 1. 运行

> ⚠️ **必须通过 HTTP 打开**。ES Module 与本地 `.glb` 都受同源策略限制，直接双击 `index.html`（file://）会失败。

**方式一（推荐）**：双击本目录下的 `启动.bat`，脚本会自动启动本地服务器并打开浏览器。

> `启动.bat` 是**纯 ASCII** 的引导文件，只负责调用 `start.ps1`（UTF-8 带 BOM）。
> 为什么不把中文直接写进 .bat：cmd.exe 按**字节偏移**定位批处理文件的下一行，
> 而一个中文字符在 UTF-8 下占 3 字节、在 cmd 默认的 GBK 下占 2 字节；
> 即使开头写了 `chcp 65001`，解析器仍会跳进行中间，把脚本拆散成
> `'7.0.0.1:' 不是内部或外部命令` 这类错误。逻辑放进 PowerShell 更可靠。
>
> 启动流程是**先起服务器 → 轮询到页面真的能返回 → 再开浏览器**。
> Python 绑定端口约需 0.6 秒，如果先开浏览器，已在运行的 Edge 会抢在前面访问，
> 页面就会显示「127.0.0.1 拒绝连接」。
>
> 轮询时校验的不只是「端口有人监听」，还会检查返回内容里有没有 `app.css`。
> 这样万一端口被别的程序占着，脚本会明确报错，而不是开出一个空页面。
> 重复双击也安全：若检测到端口上已在运行本项目，脚本直接复用、不会再起一个进程。

**方式二**：在本目录执行任意静态服务器，例如

```bat
python -m http.server 8080 --bind 127.0.0.1
:: 然后浏览器打开 http://127.0.0.1:8080/
```

可选 URL 参数：`?view=overview|top|test|aisle|pumps|boiler|tank|cr`，直接进入指定机位。

```

├── 启动.bat                  引导文件（纯 ASCII，调用 start.ps1）

│   ├── sim.js                工艺仿真内核（温度/流量/功率/COP/报警）
│   ├── scene.js              渲染器、环境光照、地形、控制器
│   ├── flow.js               管道流向动画（自定义着色器流带）

└── IndustrialPlantRoom.glb   场景模型
```

## 3. 功能

| 模块 | 说明 |
| --- | --- |
| **三维场景** | 40 × 25 m 厂房：8 台风冷热泵（试验区 2 排 4 列）、4 台离心水泵、1 台蒸汽锅炉、1 座 30 m³ 不锈钢水箱、1 台吊顶风机盘管、6 组压力表、33 条 DN200 冷热管道 |
| **实时仿真** | 50 Hz 步进：供/回水温度、温差、流量、机组负载、功率、COP、累计电量；机组与水泵按负载自动加卸载 |
| **流向动画** | 供水（红）/ 回水（蓝）管道内流动光带，方向与流速随仿真流量实时变化 |
| **状态光环** | 设备底部状态色环：运行 / 待机 / 故障 / 离线 / 检修 |
| **三维标签** | 21 个设备标签随相机实时投影，含状态圆点、位号与中文名称；离开视锥自动移出 DOM |
| **设备树** | 左侧按系统分组（热源 / 蓄水 / 输配 / 控制室 / 压力测点）列出全部设备与实时值，点击定位 |
| **KPI 面板** | 8 项核心指标 + 顶部 6 项汇总条 + 系统状态徽章 |
| **趋势曲线** | 供水温度 / 回水温度 / COP 三条实时曲线（60 s 滚动窗口） |
| **详情面板** | 选中设备后显示铭牌、运行参数、**实测点位表**（对应控制原理图的 11 类信号）与操作按钮 |
| **点位监视** | 点位类型严格对齐 PDF 控制原理图：水泵启停控制(DO)、水泵运行(DI)、水泵故障(DI)、手/自动状态(DI)、水泵频率调节及反馈(AO/AI)、温度传感器(AI)、压力传感器(AI)、液位传感器(AI)、阀门开关状态(DI)、阀门开关控制(DO)、高级协议(BMS) |
| **事件流** | 底部实时事件与报警滚动记录，按 info / warn / fault 分级着色 |
| **操作命令** | 启停、手/自动切换、阀门开闭、故障复位、参数下发，均作用于仿真内核并即时反映到三维场景 |
| **图层控制** | 设备模型 / 管道流向 / 状态光环 / 设备标签 / 分区标线 / 建筑构件 6 个图层独立开关 |
| **机位预设** | 总览、俯视、试验区、主通道、水泵房、锅炉房、水箱、控制室 8 个机位，带平滑飞行过渡 |

## 5. 坐标约定

GLB 以 `export_yup=True` 导出，故 **Blender (x, y, z) → glTF (x, z, −y)**。
`js/config.js` 中的 `b2g()` / `b2gPath()` 负责换算，设备与管道坐标均以 Blender 坐标书写，
与建模脚本 `models/00_SceneLayout.py` 保持一一对应，便于模型改动后同步。

## 6. 性能

3053 个网格按 `几何体 | 材质 | 图层` 键自动合批为 **951 个 InstancedMesh**，
总绘制调用约 250 – 1030（随视锥变化），三角面 13 万 – 50 万，桌面独显可稳定 60 fps。
阴影贴图在首帧烘焙后关闭自动更新（`shadowMap.autoUpdate = false`）。
